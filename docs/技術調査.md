# 技術調査・実装方針

[要件定義 v1.0](要件定義書.md) 第12章の調査結果と実装候補をまとめる。調査対象は Minecraft 1.20.1、Forge 47.4.10、Dragon Mounts: Legacy 1.2.3-beta、Curios API 5.14.1+1.20.1。

## Dragon Mounts: Legacy

- 通常個体は `dragonmounts:dragon` の `TameableDragon`。Minecraft の `TamableAnimal` を継承する。成長段階と品種に応じて当たり判定が変わる。 [Entity 登録](https://github.com/MWall541/Dragon-Mounts-Legacy/blob/1.20.1-1.2.3-beta/src/main/java/com/github/kay9/dragonmounts/DMLRegistry.java#L46) · [TameableDragon](https://github.com/MWall541/Dragon-Mounts-Legacy/blob/1.20.1-1.2.3-beta/src/main/java/com/github/kay9/dragonmounts/dragon/TameableDragon.java#L81)
- `mobInteract` が品種ごとの懐きアイテムを判定し、サーバーで抽選する。成功時の `tamedFor` は所有者 UUID と懐き状態を直接設定するため、Forge の `AnimalTameEvent` には頼れない。まずサーバー側の `PlayerInteractEvent.EntityInteract` で未懐きだった対象を記録し、処理完了後に同じプレイヤーへ懐いた場合だけ発行する方法を検証する。懐きアイテムや成功率は DML に委ねる。 [Forge 右クリックイベント](https://github.com/MinecraftForge/MinecraftForge/blob/1.20.1/src/main/java/net/minecraftforge/event/entity/player/PlayerInteractEvent.java#L85) · [DML 右クリック処理](https://github.com/MWall541/Dragon-Mounts-Legacy/blob/1.20.1-1.2.3-beta/src/main/java/com/github/kay9/dragonmounts/dragon/TameableDragon.java#L426) · [所有者設定](https://github.com/MWall541/Dragon-Mounts-Legacy/blob/1.20.1-1.2.3-beta/src/main/java/com/github/kay9/dragonmounts/dragon/TameableDragon.java#L644)
- `mobInteract` の冒頭でアイテム固有の対 Mob 操作を呼ぶ。Minecraft 標準の `NameTagItem` は名前付きの名札を生存中の対象に使うと `setCustomName` を呼ぶ。名前の初回設定と変更を実機で確かめる。無名時は品種の翻訳キー、命名済みなら個体名を指輪の表示に使う。チェストなどの指輪は取り出した際に最新名へ同期する案とする。 [アイテム操作](https://github.com/MWall541/Dragon-Mounts-Legacy/blob/1.20.1-1.2.3-beta/src/main/java/com/github/kay9/dragonmounts/dragon/TameableDragon.java#L426) · [品種名](https://github.com/MWall541/Dragon-Mounts-Legacy/blob/1.20.1-1.2.3-beta/src/main/java/com/github/kay9/dragonmounts/dragon/TameableDragon.java#L624)
- DML の保存処理は継承元に加えて品種、鞍、繁殖回数、能力データを扱い、読込時には品種を先に設定する。座り指示と追従 AI も DML が管理する。通常個体の NBT を使った往復で、体力、成長、名前、所有者、座り指示、鞍を検証する。復元後の初回 tick も確認する。飛行フラグは接地状況に応じて更新され、騎乗関係は別途検証が必要。 [保存と読込](https://github.com/MWall541/Dragon-Mounts-Legacy/blob/1.20.1-1.2.3-beta/src/main/java/com/github/kay9/dragonmounts/dragon/TameableDragon.java#L190) · [飛行の更新](https://github.com/MWall541/Dragon-Mounts-Legacy/blob/1.20.1-1.2.3-beta/src/main/java/com/github/kay9/dragonmounts/dragon/TameableDragon.java#L323)

## Curios と操作入力

- `curios:ring` タグを指輪に付け、Curios のデータパック設定でプレイヤーに既存の `ring` スロットを割り当てる。通常装備の可否は `ICurioItem#canEquip` で所有者、スロット種別、既装備数を確認する。専用キーから操作するときにも、サーバー上で有効な指輪が1個だけ装備されていることを確認する。 [アイテムタグ](https://docs.illusivesoulworks.com/1.20.x/curios/items/assign-slots) · [スロット割り当て](https://docs.illusivesoulworks.com/1.20.x/curios/slots/entity-register) · [スロット一覧](https://docs.illusivesoulworks.com/1.20.x/curios/slots/preset-slots)
- 取り外しの検知には `onUnequip` を候補とし、死亡やログアウト由来の装備変化で状態を誤更新しないよう実行順を検証する。キー登録はクライアント側の `RegisterKeyMappingsEvent` を使う。通信は切り替え要求だけを送り、対象の特定と状態更新はサーバースレッドで行う。 [キーバインド](https://docs.minecraftforge.net/en/1.20.1/misc/keymappings/) · [Forge ネットワーク API](https://docs.minecraftforge.net/en/1.20.1/networking/simpleimpl/)

## 永続化と状態遷移の設計案

- オーバーワールドの `SavedData` に、個体 UUID、初回所有者、発行済み情報、状態を記録する。格納中の個体はここに復元用 NBT を保持する。通常個体の探索では最終確認ディメンションとチャンクを参照する。未ロードで見つからない個体を追加で召喚しない。 [Forge Saved Data](https://docs.minecraftforge.net/en/1.20.1/datastorage/saveddata/)
- 通常召喚は復元した個体の当たり判定で候補地点を検査する。空間不足や Entity の追加に失敗した場合は現在の状態を維持する。通常個体の死亡は記録に残し、古い指輪からの復元を止める。
- 死亡の検知には `LivingDeathEvent` を使い、取り消された死亡を確定扱いしない。ログイン・ログアウト・移動時は `PlayerEvent` の `PlayerLoggedInEvent`、`PlayerLoggedOutEvent`、`PlayerChangedDimensionEvent` を使い、表示用 Entity を装備と保存状態に合わせる。 [死亡イベント](https://github.com/MinecraftForge/MinecraftForge/blob/1.20.1/src/main/java/net/minecraftforge/event/entity/living/LivingDeathEvent.java) · [プレイヤーイベント](https://github.com/MinecraftForge/MinecraftForge/blob/1.20.1/src/main/java/net/minecraftforge/event/entity/player/PlayerEvent.java)
- Entity のチャンク保存と `SavedData` の書き込みは別なので、途中でサーバーが停止した場合も検証する。ロード時に同一 UUID の実体と記録を照合し、実体の所在が確定するまで新しい個体を作らない。
- ミニオンは専用 Entity として追従に必要な情報だけを持たせる。配布 JAR の `DragonModel` と `DragonRenderer` は `TameableDragon` を型引数に取り、通常のアニメーション更新もその tick に依存する。専用 Entity のレンダラーでモデルパーツと品種テクスチャを再利用できるか試作する。後方・肩・非表示の切り替えはクライアント側の描画で扱う。 [DML のクライアントアニメーション更新](https://github.com/MWall541/Dragon-Mounts-Legacy/blob/1.20.1-1.2.3-beta/src/main/java/com/github/kay9/dragonmounts/dragon/TameableDragon.java#L323)

## 実装前に確認する仕様

| 項目 | 検討案 |
| --- | --- |
| ミニオンの指輪を外して再装備する場合 | 格納状態に移し、取り外しによる格納だけに再表示フラグを残す。死亡後は装備してキー操作するまで格納を維持する。 |
| プレイヤー死亡時に格納する個体の範囲 | 装備中の指輪に対応する1体を候補とする。所有する全個体を対象にする場合は、別ディメンションや未ロードチャンクの処理も定義する。 |
| 「成長したドラゴン」の条件 | DML の懐き処理は成長で制限されない。若い個体でも懐いた時点で発行する案と、成長後に発行する案がある。 |
| 騎乗中のミニオン化・再ログイン | 騎乗中のミニオン化は拒否する案。再ログインは Minecraft 標準の騎乗復元を先に検証し、失敗時の救済を追加する。 |

## 実装順と確認項目

1. **指輪の発行と装備** — 懐き成功で1個だけ発行されること、別プレイヤーの装備拒否、2個目の装備拒否、再起動後の発行済み判定を確認する。
2. **通常個体の格納と復元** — 同じ UUID と保存状態での復元、障害物による失敗時の保持、未ロード個体や複製された指輪からの二重召喚防止、死亡済み個体の復元拒否を確認する。
3. **ミニオンとライフサイクル** — 追従、見た目の切り替え、装備解除と再装備、死亡、ログアウト、ディメンション移動を確認する。統合サーバーと専用サーバーの両方で、複数のプレイヤーと通常個体を扱う。

## 格納・復元の基盤

- 発行履歴と既存の指輪の形式を引き継ぐ。操作ごとにサーバーで装備中の指輪、発行履歴、個体の所有者を照合する。格納はロード済みの通常個体だけを対象とし、騎乗中・乗客を乗せている・リードでつながれている個体は格納を保留する。
- 個体の状態はワールドの `data/dmlcompanion_dragons.dat` に書き込む。格納時は NBT の書き込み完了後に通常個体を取り除く。復元時はプレイヤー前方の一箇所を体格に合わせて検査し、追加した個体をディメンションに保存する。ディスク上の UUID と復元時に付けた識別子を確認してから格納データを解除する。復元時はディメンション保存の分だけ処理時間がかかるため、専用キーへ接続する段階で実ワールドでの所要時間を測る。
- 通常召喚中の個体が死亡で除去されたときは、死亡を記録する。再起動後に読み込まれた古い個体は、格納・死亡状態または復元時の識別子で判定する。
- Gradle の `checkDragonStorage` は、NBT の再読み込み、過去の実体の拒否、書き込みエラー時の状態保持、Entity リージョンファイルでの保存確認を検証する。バージョン 0.2.0 では専用キーを格納と通常召喚に接続した。プレイヤーの操作と実際のワールドでの召喚は [動作確認手順](../README.md#格納召喚の動作確認) を使う。
